# 技術スタックと初期実装方針

## 決定事項

### パスワード管理機能

**実装方針**
- リポジトリ自動同期は不要（将来的な拡張として残す）
- オプションページで手動入力・編集できる機能を実装
- 入力したパスワード情報をChrome Storage APIで保存
- コンテンツスクリプトでフォームへの自動入力機能を提供

**データ構造（案）**
- URL/ドメイン
- ユーザー名
- パスワード
- メモ（オプション）

### スクリーンショット機能

**実装方針**
- キーボードショートカットで起動
- ブラウザの表示部分（viewport）をキャプチャ
- トリミング機能付きショートカットも提供

### 技術スタック

- **言語**: TypeScript
- **パッケージマネージャー**: pnpm
- **UIフレームワーク**: Vue.js（オプションページ）
- **ビルドツール**: Vite（Chrome拡張対応設定）
- **Chrome Extension**: Manifest V3

### ディレクトリ構成（案）

```
ss-bg/
├── src/
│   ├── background/      # Service Worker
│   ├── content/         # Content Scripts
│   ├── popup/           # ポップアップUI

```

## 検討が必要な事項

### 1. パスワード保存のセキュリティ

**現状の懸念**
- Chrome Storage APIは平文保存
- 拡張機能の領域は他の拡張からは隔離されているが、完全に安全とは言えない

**選択肢**
- A. 平文で保存（シンプルだが安全性低）
- B. マスターパスワードでAES暗号化して保存（セキュリティ向上、UX低下）
- C. Web Crypto APIで暗号化（ブラウザ依存の鍵管理）

### 2. パスワード自動入力のトリガー

**選択肢**
- A. キーボードショートカット（Ctrl+Shift+P）のみ
- B. フォーカス時に候補をドロップダウン表示
- C. コンテキストメニュー（右クリック）
- D. 複数の方法を提供

### 3. スクリーンショットの保存先

**選択肢**
- A. ダウンロードフォルダに自動保存
- B. クリップボードにコピー
- C. 両方を選択可能
- D. オプションで保存先を指定可能

### 4. トリミング機能のUI

**実装方法**
- Canvas overlayでドラッグ選択UI
- 実装コストが高いため、優先度を下げることも検討

### 5. ポップアップUIの必要性

**検討点**
- オプションページがあれば、ポップアップは不要かもしれない
- または簡易的なパスワード一覧・クイックアクションのみ提供

### 6. URLマッチングの方法

**パスワード自動入力時のURL判定**
- 完全一致
- ドメイン一致
- 正規表現マッチング
- 複数URLを登録可能にするか

## 優先順位（提案）

### Phase 1: 最小限の動作実装
1. オプションページでパスワード手動入力・保存（暗号化なし）
2. キーボードショートカットでパスワード自動入力
3. 基本的なスクリーンショット機能（保存のみ）

### Phase 2: 機能拡張
4. パスワードの暗号化保存
5. スクリーンショットのトリミング機能
6. UIの改善

### Phase 3: 高度な機能（オプション）
7. GPG連携
8. リポジトリ同期機能
