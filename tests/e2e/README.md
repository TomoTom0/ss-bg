# E2Eテスト設計

## 概要

Chrome拡張機能としての統合テストを実施する。Playwrightを使用して、実際のブラウザ環境で拡張機能の動作を検証する。

## テスト環境

- Playwright + Chromium
- 拡張機能のビルド済みdist/を読み込み
- WebAuthn APIのモック（Playwrightでは実際のWebAuthn認証は困難）

## テスト項目

### 1. 拡張機能のロード
- [ ] 拡張機能が正常にロードされる
- [ ] manifest.jsonが正しく読み込まれる
- [ ] Service Workerが起動する
- [ ] Content Scriptが注入される

### 2. Popup UI
- [ ] Popupが開ける
- [ ] 初期状態（未認証）が表示される
- [ ] 設定リンクが機能する

### 3. Options UI
- [ ] Options ページが開ける
- [ ] パスワード一覧が表示される（初期は空）
- [ ] 設定項目が表示される

### 4. Content Script
- [ ] パスワードフィールドが検出される
- [ ] Shadow DOMが作成される
- [ ] オートフィルアイコンが表示される

### 5. スクリーンショット機能
- [ ] キーボードショートカットが動作する
- [ ] スクリーンショットが撮影される
- [ ] ダウンロードが開始される

## 制約事項

### WebAuthn認証
実際のWebAuthn認証は以下の理由で困難：
1. TPM/セキュリティキーへのアクセスが必要
2. Playwrightでは仮想認証器のサポートが限定的
3. PRF拡張のモックが複雑

**対応方針**:
- WebAuthn認証をスキップするテストモードを実装
- または、認証部分は単体テストで担保し、E2Eでは認証後の状態をモックする

### Windows Hello
Windows Hello（生体認証）も同様の理由で自動テスト困難。

## テストモードの設計

環境変数 `E2E_TEST_MODE=true` で以下の動作に変更：
1. WebAuthn認証をスキップして自動的にセッションを作成
2. ダミーの暗号化キーを使用
3. 認証なしでパスワード操作を許可

これにより、E2Eテストでは認証以外の機能を検証できる。

## 実装方針

1. テストモード用の環境変数チェック機能を追加
2. 基本的なロード・UI表示のテストを実装
3. Content ScriptのDOM操作テストを実装
4. スクリーンショット機能のテストを実装

認証機能は単体テストで十分に検証済みのため、E2Eでは統合動作を確認する。
